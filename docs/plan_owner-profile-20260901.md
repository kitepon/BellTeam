# BellTeam オーナープロフィール計画

## 目的

Web UIからオーナーのプロフィールを管理し、BellTeamが全Botへ最新のオーナー情報を自動で渡す。

## 受入条件

- 左上のBellTeamアイコンをオーナーのアバターとして表示し、押すとプロフィール設定画面を開く。
- アバター、名前、プロフィール、XプロフィールURL、GitHubプロフィールURL、名称付きのその他URLを保存・再表示できる。
- GitHubはプロフィールURLを正本とし、アカウント名だけの入力は持たない。
- オーナープロフィールは`/srv/bellteam/owner/profile.json`だけを永続化の正本とする。
- Web APIとBellTeam MCPの`get_owner_profile`が同じ正本を返す。
- セッション起動、ユーザー会話、Bot間直接連絡、ルーム発言、予定実行で、現在のオーナープロフィールをBellTeamが自動で文脈へ添付する。
- 共通規範はプロフィール値を複製せず、BellTeamが添付するオーナー情報と`get_owner_profile`を正本として扱うよう各Botを誘導する。
- プロフィールを更新した後は、Botの再起動を待たず、次のBellTeam配送から新しい内容を受け取る。
- 既存のBot、記憶、RAG、会話、予定を維持したまま本番へ反映する。

## 非目標

- メールアドレス、住所、電話番号、決済情報は保存しない。
- XやGitHubへログインせず、外部APIからプロフィールを自動取得しない。
- オーナープロフィールをBotの長期記憶や共通規範の散文へ複製しない。
- プロフィール更新を理由に全Botのセッションを再起動しない。

## 設計

- `OwnerProfile`サービスがJSON正本の初期化、取得、更新、検証を所有する。
- 名前は必須とし、プロフィールとURLは任意とする。その他URLは`label`と`url`の組を複数持つ。
- URLは`https:`または`http:`だけを受け付ける。XとGitHubのURLはそれぞれ対応する公開プロフィールのhostだけを受け付ける。
- Web APIは`GET /api/owner`と`PATCH /api/owner`を提供する。
- 配送層は保存値から一つのオーナー文脈を作り、各プロンプトの既存メタデータと一緒に渡す。
- アバター編集は既存Botの画像選択、切り抜き、data URL保存を再利用する。
- 既存プロフィールがない時は、名前を「オーナー」、その他を空として初期化する。

## 作業分類

- F: 永続化正本、Web API、MCP公開契約、全配送経路への自動添付、本番配備と最終受入。
- A: Web設定画面、アバター編集、表示更新、focused test。
- H: なし。

## 実行順

1. 現在の保存、配送、MCP、UI契約を実コードで確認する。
2. OwnerProfileの保存契約とfocused testを作る。
3. Web API、MCP、全配送文脈を同じサービスへ接続する。
4. 左上アイコンと設定画面を実装する。
5. focused testと関連testを通す。
6. 最終確認としてfull regressionを一度実行する。
7. 本番へ配備し、公開API、画面、配送文脈をsmoke確認する。
8. 現行設計と現在状況を更新し、最終裁定を記録する。

## 並列化の裁定

保存サービス、配送文脈、Web UIは同じプロフィールschemaと既存の`web/app.js`周辺へ連鎖する。子へ分割すると同一repo内の受入と統合が増えるため、親が直列に実装する。Latticeは未初期化であり、オーナーから新規導入の指示もないため導入しない。

## 既知の罠

- 共通規範に現在値を書き込むと、プロフィール更新時に散文とJSONがずれる。
- セッション起動時だけ添付すると、稼働中セッションがプロフィール更新を受け取れない。
- UIだけでURLを検証すると、MCPやAPIから不正値を保存できる。
- アバターdata URLをプロンプトへ入れると文脈が肥大化するため、Botへ渡すプロフィール文には画像本体を含めない。
- Botが0体でも配送文脈のテストはfixtureで成立させ、本番smokeのためにBotを新規作成しない。

## 検証

- OwnerProfileの作成、更新、再読込、URL検証を一時ディレクトリで確認する。
- Web APIとMCPが同じ保存値を返すことを確認する。
- セッション起動、ユーザー会話、直接連絡、ルーム、予定のfocused testでオーナー文脈を確認する。
- デスクトップとモバイル幅で設定画面の表示、保存、再読込を確認する。
- `npm test`をPhase最終確認として一度実行する。
- 本番では使い捨てプロフィール値に置換せず、初期値の取得と公開資産、コンテナhealthを確認する。
