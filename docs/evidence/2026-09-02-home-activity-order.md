# トップページ最新アクション順の検証

## 結論

トップページのメンバー欄とルーム欄を、それぞれ最後のアクションが新しい順へ変更し、本番へ配備した。既読は並び順に影響せず、未読印だけを消す。

## 実装

- `web/activity-order.js`へ、最新アクション日時の降順、日時なしは末尾、同時刻は元の順番を保つ並び替えを集約した。
- `web/app.js`はメンバーとルームを別々に並べ、ユーザー自身の送信を除く最新アクションへ未読印を付ける。
- 最後に読んだアクションIDはブラウザ端末内へ保存する。会話を開いたことや既読値は並び替えへ使わない。
- `src/http-server.mjs`はメンバーの最新アクションIDを一覧APIへ返し、並び替え用モジュールを静的配信する。

## 検証

- ローカルと本番サーバーでNodeテスト108件が全件成功した。
- 公開URLと`/healthz`はHTTP 200、コンテナはhealthy、直近エラーは0件だった。
- 公開画面を390px幅で確認し、27メンバー・7ルームのDOM順が一覧APIから算出した最新アクション順と完全一致した。
- 未読の会話を1件開いた後、未読印が消え、全34件のDOM順が開く前と一致した。
- 390px幅で横方向のはみ出しはなかった。
- ローカルと本番の製品ファイル35件は同じSHA-256 manifestだった。
