# BellTeam Aiterm会話・ルーム 計画

## 目的

Botごとに一つの継続Aitermセッションを持たせ、ユーザーとの通常会話、人格が分かるBot間通信、複数Botのルーム会話を同じWeb UIとMCPから使えるようにする。

## 受入条件

- ユーザーが個別チャットへ本文または画像を送ると、対象BotのAitermセッションへ一つのターンとして渡り、完了後の確定回答が自動でチャットへ表示される。
- Bot作成時は一つのプロジェクトフォルダと一つの継続セッションを作り、作成内容を伝えて挨拶を求めた最初のターンを実行する。
- Botプロフィールは自動生成ID、名前、役割を分けて持ち、UIでは`役割【名前】`と表示できる。
- `sendmessage(target, message, image?)`は送信者ID、名前、役割をBellTeamが呼出元から確定し、相手Botへ非同期で届ける。
- Bot間の送受信は個別チャットへ一行の活動記録として表示し、開いた時だけ本文と画像の有無を確認できる。
- UI画像は対象Botへ実画像として渡し、送信元ターン中だけ一時ファイルを維持する。ログには画像の有無だけを残す。
- ルームは自動生成ID、名前、目的、代表Bot、メンバー、予定を持つ。代表Botはメンバーだけを指定でき、退室時は未設定になる。
- ルーム発言は現在のメンバーへ並列配送し、各Botへ部屋名、目的、代表、全メンバー、発言者、宛先、通常発言か予定実行かを毎回渡す。
- `sendroommessage(room, message, image?, targets?)`は`targets`省略時に全メンバー、指定時に対象Botだけへ届ける。送信者自身へは配送しないが、ルーム履歴には残す。
- ルームごとに`schedule.json`一ファイルを持ち、全員または一部メンバーを宛先にできる。予定実行は代表Botの現在発言を装わない。
- Web UIからBotとルームを一覧・作成・編集・削除でき、個別チャットとルームチャットを使える。
- Web UIで可能なBot、ルーム、メッセージ、予定の操作をコンテナ内の共通MCPからも実行できる。
- 既存のBot、プロフィール、Bot予定、個別チャット履歴を維持したまま本番へ反映する。

## 非目標

- 一つのプロジェクトへ複数Botを置かない。
- Bot間メッセージを受けたBotの最終回答を送信元へ自動転送しない。
- 画像本体をBellTeamの会話資産として永続保存しない。
- 過去のルーム文脈を毎回すべてプロンプトへ複製しない。
- 配送失敗の自動再試行、権限階層、承認フローは作らない。

## 設計

- BellTeamは一つのAiterm MCPプロセスを持ち、Bot IDごとの継続セッションを管理する。CLI固有差はAitermだけが扱う。
- Aitermのdispatchが返す`event_cursor`で`aiterm-wait`を一回待ち、`outcome=done`後に`pty_read(agent_transcript=true)`で確定回答を取得する。
- ユーザー会話だけは確定回答をユーザー向けログへ自動追加する。Bot間とルーム配送は受理時点で完了する。
- `/srv/bellteam/rooms/<room-id>/room.json`をルーム設定、同じフォルダの`schedule.json`を予定、`messages.jsonl`を履歴の正本にする。
- ルーム削除はこのフォルダを削除し、設定、予定、履歴を一緒に消す。参加BotとBotの個別記憶は残す。
- ルームの代表権限はMCP呼出元Bot IDとルーム設定を照合する。ユーザー操作はWeb UIから常に許可する。
- 個別メッセージとルームメッセージは送信時点の名前と役割を記録し、後のプロフィール変更で書き換えない。

## 既知の罠

- `aiterm-wait`は終了コードだけで完了判定しない。`outcome=timeout`は未完了として同じcursorから待ち直し、`done`の後だけ回答を読む。
- `pty_read(agent_transcript=true)`を完了前に繰り返さない。
- 画像の一時ファイルは送信元BotがMCPで転送できるよう、そのターンの完了まで削除しない。
- Bot間とルーム配送で受信Botの最終回答を自動転送すると、意図しない会話ループになるため行わない。
- ルーム配送は配送開始時の設定を一つのsnapshotとして使い、並列処理中にメンバー情報を混在させない。

## 検証

- Aitermクライアント、完了待ち、確定回答取得、画像入力のfocused test。
- 送信者人格、Bot間非同期配送、ログsnapshotのfocused test。
- ルーム設定、全員配送、限定配送、代表Bot管理、予定実行のfocused test。
- HTTP APIとMCPのfocused test。
- モバイル幅でBot作成、個別画像会話、ルーム作成、ルーム発言、限定宛先を確認する。
- 関連testを一回通した後、本番でAitermを使った個別会話とBot間・ルーム配送を確認する。

## 並列化判断

Aitermセッション、メッセージ保存、MCP、HTTP API、UIが同じデータ契約を順に共有する。今回の実装は一つの作業ツリーで直列に進め、別writerは起動しない。
