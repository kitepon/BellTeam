# ADR 0004: Aiterm継続会話とルーム配送を共通基盤にする

## Status

Accepted — 2026-08-31

## Context

既存実装はtmuxへ文字列を送るだけで、AIのターン完了と確定回答を検知できなかった。Bot間通信にも送信者の名前と役割がなく、複数Botが仕事を共有するルームも存在しなかった。

## Decision

- 一つのBotは一つのプロジェクトフォルダと一つのAiterm継続セッションを持つ。
- ユーザーとの通常会話はAitermの完了通知後に確定回答を取得し、BellTeamが自動でチャットへ記録する。
- Bot間とルームの配送は非同期とし、受信Botの最終回答は自動転送しない。
- 直接メッセージとルームメッセージは、呼出元から確定した送信者ID、名前、役割を含む。
- ルームは名前、目的、代表Bot、メンバー、予定、履歴をルーム単位で所有する。
- ルーム発言は現在のルーム設定snapshotを付け、対象メンバーのAitermセッションへ並列配送する。
- ルーム内の限定宛先を許し、非対象Botには配送しない。
- 代表Botはルームのメンバーだけが務め、代表が退室した時は未設定にする。
- 画像はAI入力として直接渡し、BellTeamの会話資産として保存しない。
- Web UIの操作面とコンテナ内グローバルMCPの操作面は同じアプリケーション処理を使う。
- 本作業は個別会話、非同期配送、ルーム、UI/MCP、本番受入が連鎖するため統括レーンで行う。別workerは使わない。

## Verification

- Aitermの`event_cursor`付き完了待ちと確定回答取得
- 名前と役割を含むBot間画像メッセージ
- ルーム全員配送、限定配送、代表変更、予定実行
- Web UIとMCPの同一操作結果
- 公開環境での個別会話、Bot間通信、ルーム通信
