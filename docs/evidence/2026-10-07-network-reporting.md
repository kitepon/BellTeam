# Appleアプリの通信失敗の報告

通信失敗は、操作を扱った後に確認できた実害から重大度を付ける。正常な取消は送らず、保存済み内容の読み戻しで操作成功を確認できた失敗は参考記録にする。原因未確定の失敗はそのまま明示し、通信環境の障害とアプリの欠陥を同一視しない。

判断の正本は [ServerManagerの通信失敗の報告要件](https://github.com/kitepon/ServerManager/blob/ef578fe/bughub/NETWORK_REPORTING.md)。配布候補、試験結果、署名・Apple処理・端末への導入の状態は [準備状況](../subscription-setup.json) の `integration.networkReportingRepair` に置く。

## 操作の対処後に報告する

`BellAPI` は通信・応答の失敗を呼出元へ返し、そこで先に診断を登録しない。画面や `AppStore`・`BillingStore` が表示、入力保持、保存結果の照合、再接続または停止を扱った後、`BellDiagnostics` へ確認できた影響を渡す。

| 確認した影響 | 重大度と根拠 |
| --- | --- |
| 保存内容の読み戻しが一致し、操作成功を確認できた | `info`。`user_impact=none` と `app_handling=saved_content_confirmed_by_read` を残す。PATCHを再送しない。 |
| 読み取りができない、更新の再接続中、通知や購読の一機能を使えない | `warn`。データ保持・エラー表示・復旧方法と未確認部分を残す。表示や入力保持だけで影響なしとは判定しない。 |
| 書き込みの応答を失い、結果が分からない | `warn`。入力の保持と、再操作前に状態を確認する案内を記録する。秘密入力は従来の消去方針を維持して記録する。 |
| 接続開始に失敗し、アプリを使える状態まで進めない | `high`。機能停止の影響と手動の再接続手段を記録する。回線の状態だけでアプリの欠陥とは判定しない。 |
| 正常なTask取消 | 報告しない。予期しない取消は正常取消へ読み替えない。 |

根拠は既存の `diagnostic_log` の行に置き、BellTeam内の受け口へだけ合意済みの任意項目 `severity` を渡す。BugHubのJSON契約は増やさない。エラーコードは事象の種類を示すために残し、原因・担当を断定する値として使わない。報告に本文・入力値・秘密情報は含めない。

## 維持する対処

GETの接続切断からの一度の取り直し、SSEの復旧、正常取消、送信中の背景実行時間、入力保持、認証の復旧、秘密入力の消去方針は既存処理を使う。取り直しでGETが成功した場合は失敗を登録しない。書き込みは自動で再送しない。

送信の結果が分からない場合の案内を会話の入力欄の上へ重ねて表示する。入力欄の高さは変えず、再操作前に現在の状態を更新して確認する手順まで複数行で読めるようにした。キーボード表示中の入力欄と案内全文を画像で確認し、失敗後に入力欄をタップして追記できることも確かめた。

## 隔離した受け口での確認

Simulatorの画面から、現在の `createBellTeamServer` と `Diagnostics` を使うloopbackの受け口へ報告した。試験データは専用領域へ保存し、本番へ合成報告は送らない。

送信の応答が切れた場合は、本文が入力欄へ戻り、結果未確認の案内が表示され、`warn`・`open` の報告が届いた。POSTは一度だけだった。メンバー設定のPATCHで応答を失った場合は、読み戻した保存内容が一致し、根拠付きの `info`・`resolved` が届いた。PATCHの再送は無かった。

予定取得中にホームへ移った場合は、未完了の接続が実際に閉じられ、診断の登録は無かった。前面へ戻ると予定を取得して表示した。成功表示だけで取消成功とはせず、受け口の接続状態も確認した。

## 配布と受入の順序

重大度を扱えるサーバーの反映をトロニーが確認してから、TestFlight内部配布と端末への導入を行う。古いサーバーは `severity` を読み捨て、参考記録まで固定の重大度で再登録するため、この順序を守る。署名・アップロードは先に準備できるが、自動配布の設定も確認する。

MacはTestFlightで更新し、導入版・署名・起動・既存接続・通常画面を確かめる。iPhoneはTestFlightの更新と一度の起動だけ本人に依頼し、通常利用で確認する。取りやめた実機通信試験と、過去の通信環境の根因追跡は再開しない。既存診断の原本・累計・時刻・解決注記は保持する。
