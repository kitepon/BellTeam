# BellTeam Bot管理・自動実行 計画

## 目的

ユーザーがWeb UIからBotを追加・編集でき、各BotがMCPから自分のプロフィールと自動実行予定を管理できるようにする。

## 受入条件

- Web UIから名前、人格、役割、アバター、CLI種別を指定してBotを追加できる。
- Web UIから既存Botの名前、人格、役割、アバターを編集できる。
- 日時指定の一回実行、毎時、毎日、曜日指定、cron式の予定を追加・削除できる。
- プロフィールと予定はBotのプロジェクトフォルダへ永続化され、予定はBotごとに`schedule.json`一ファイルを使う。
- MCPからBot追加、自分のプロフィール変更、予定の追加・一覧・削除ができる。
- 実行時刻になると対象Botがtmux上で起動し、設定した指示を直接受け取る。
- コンテナ再起動後もBotと予定が残る。
- 公開URLから追加・編集・予定登録ができ、既存のユーザー会話とBot間通信が動き続ける。

## 非目標

- Botの削除は実装しない。
- 失敗した実行の自動再試行や、停止中に溜まった回数分の再生は行わない。
- hostのcrontabは変更しない。
- Peertableの円卓と着席管理は変更しない。

## 設計

- `/srv/bellteam/bots/<bot-id>/bot.json`をプロフィールの正本にする。
- `/srv/bellteam/bots/<bot-id>/schedule.json`をそのBotの予定の正本にする。
- BellTeam内のschedulerが予定を読み、tmux配達の既存経路で指示を送る。
- 一回実行はISO日時、反復実行はcron式として保存する。Web UIの毎時・毎日・曜日指定はcron式へ変換する。
- 既存の`config/bots.json`は初回起動時のseedとして残す。

## 既知の罠

- Bot追加後に既存プロセスが古い固定一覧を持ち続けないよう、APIとMCPの処理前にプロフィールを再読込する。
- 人格と役割の変更は表示だけで終わらせず、Botのプロジェクト指示へ反映する。
- schedulerの通知をユーザー発言として記録しない。会話画面では自動実行の活動行として表示する。
- 一回実行をcronへ擬装しない。

## 検証

- Bot永続化、予定計算、MCP操作、HTTP APIのfocused test。
- 既存テストを含む`npm test`を最終確認として一回実行する。
- メインサーバーでBot追加、プロフィール編集、期限到来した一回実行を確認する。
- `https://team.example.com`の認証、一覧、管理API、healthを確認する。

## 並列化判断

プロフィール正本、MCP、HTTP API、schedulerが同じ保存形式を共有するため、親が一つの作業ツリーで直列に実装する。別writerは起動しない。
