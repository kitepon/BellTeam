# Web入力欄の高さ

送信失敗で本文を復元しても、入力欄は1行の高さに戻ったままだった。窓の幅を変更して折り返しが増えた場合も、次の入力が来るまで高さを測らなかった。通常のWeb画面と人工APIで両方を再現した。

`chat-input.js`に高さの測定をまとめ、入力・本文復元・消去・幅変更・font準備で呼ぶ。上限を固定120pxから5行分の実行高とpaddingへ変更し、最終行が途中で切れないようにした。5行を超える内容は内部scrollで編集でき、末尾入力中のcaretを見せる。

| 人工Chromium画面の条件 | 修正前 | 修正後 |
| --- | --- | --- |
| 4行入力→送信503→本文復元 | 必要107px、実高37px | 実高107px、本文不変 |
| 窓1400→390、追加入力なし | 必要176px、実高60px | 5行上限130px、末尾可視 |
| 12行入力の末尾へ追記 | 上限120px、端の行が部分表示 | 5行130px、末尾可視 |

同じbefore/after fixtureで上記・4行成長・1行への縮小・折り返し・合成compositionの7条件を確認。既存chat-input7件、依存準備後の既定並列全747件成功（fail/cancel/skip0）。新worktreeの初回全体は依存未配置でimportに失敗したため、同package/lockの自席既存依存へ接続して再実行した。初回原本も保持し、製品不具合の修理結果へ混ぜない。

数値と原本SHAは同名JSON参照。人工loopbackとChromiumの結果であり、実日本語IME、Apple共通入力部品、Owner実機の合格ではない。Ownerの添付画像はprivateに保持し、この証拠へ含めない。ゴール管理とMacの過去ログ修理も別の未完工程。本番反映は未実施。
