# アプリから使い始める人の導入案内

## 公開と実装

オーナーの指示で`kitepon/BellTeam`を公開へ切り替えた。公開対象のmainの履歴とGitHubの参照を確認し、署名データの検出は公開試験用の署名材と、保存した一次資料の公開サイト用データであることを確認した。匿名でソースと導入ガイドを取得できた。

アプリ初回画面の「はじめて使う」から、サーバー未接続でも導入ガイドを開ける。`docs/server-installation.md`をiPhone・iPad・Macへ同梱し、公開GitHubでも同じ内容を読む。PCとDockerの準備、公開Compose・installerの取得、起動、接続先URLの確認、AIの選択と公式認証までを案内する。

オーナーが追加した「GitHubのURLと『これセットアップしたい』をAIに渡す」という方法も掲載した。アプリではURLと依頼文を2行の文章としてコピー・共有できる。実装は`7b9dc8c`、追加案内とコピー・共有は`ef31b3f`をmainへ反映した。

## 検証と配布

- iPhoneのUI試験で、サーバー未接続でもガイドを開けること、ガイドの開閉で入力URLを失わないこと、依頼文のコピー表示を確認した。コピーされた2行の内容も一致した。
- 匿名で取得した公開のComposeとinstallerを使い、専用の空の保存先からコンテナを起動した。healthzは正常、初回状態は`select_harness`だった。
- Apple標準UI試験で、その新規サーバーへアプリから接続し、Claude・Codex・Grok・Cursorの選択画面まで進めた。成功1件・失敗なし・スキップなし。認証とAIへの送信は行っていない。
- Mac Catalystのビルドと実画面を確認した。Macのガイドを開く操作はJevを使った。
- Nodeの全363件が成功した。並行してmainに入った配送の変更は差分を読み、対象の11件が成功した。
- iPhone・Macとも1.0（41）を配布署名で書き出した。配布物と同梱ガイドの一致を確認し、TestFlightオーナーグループの`VALID`・`IN_BETA_TESTING`を確認した。
- 本番のデータとコンテナには変更していない。試験用コンテナ・volumeを片付け、今回起動したColimaを停止した。

Macの既存Docker環境では、導入済みComposeのプラグイン登録が欠けていた。Docker設定をバックアップし、Homebrewの公式案内に従ってプラグインの登録だけを追加した。既存の認証・接続設定は保持した。

XcodeBuildMCPの手動入力は入力完了と返したが、実際の入力欄は空だった。この結果は成功に含めていない。実サーバー接続はApple標準のXCTestで入力値と接続先画面を確認した。
