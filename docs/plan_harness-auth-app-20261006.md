# AI認証画面の配布と実認証の確認

目的は、AIの認証が切れてメンバーが止まった時に、オーナーがAppleアプリから公式認証へ入り直せること。実装・試験・両プラットフォームのTestFlight内部配布、Macへの導入・起動と認証状態の閲覧は完了した。Macから本番の本人の操作を含む確認を待っている。状態・配布物・検証結果は[準備状況の正本](subscription-setup.json)の`integration.appHarnessAuthentication`、実装と試験の説明は[検証記録](evidence/2026-10-06-app-harness-auth.md)を参照する。

## 残る作業

1. iPhoneの更新は別に確認する。本番の認証確認には導入済みのMacを使い、iPhoneの更新を前提にしない。Macでは設定のAI一覧とCodexの認証済み表示を確認した。閲覧の段階では認証を開始していない。
2. オーナーの進行GOは受領済み。トロニーが予定の完了後に実行中のCodex席が無いことを確認し、サーバーの観測を用意してから始める。
3. Cursorの開始・待ち・取消・実状態の読み直しは本番のMacで完了した。Codexは、オーナーがスマホの公式認証ページへログインしコード入力画面まで進んだら、担当の開始合図と合わせてMacアプリから開始する。公式サイトでの承認を経て、認証済みへの遷移とメンバーの応答を確認する。

Codexは開始時に今の認証を消すため、担当の直前確認と本人のログイン準備が揃ってから開始する。Macの公式サイトはTouch IDの本人操作で止まったため、スマホの公式画面を使う。試験専用の常設サーバーは無く、今回の画面試験は本番と切り離したHTTP fixtureで行った。公式認証を最後まで通したとはまだ扱わない。ASCへの再提出と本番コンテナの再起動はこの作業に含めない。

詰まった時は操作を止めてトロニーへ連絡する。トロニーのAitermの公式認証入口による入り直しは運用の復旧であり、アプリで通った確認の代わりには数えない。Codexの入り直し後の期限の確認と知らせの予定の更新はトロニーが行う。
