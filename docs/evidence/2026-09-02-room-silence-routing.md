# ルーム応答の沈黙と個別配送

確認日: 2026-09-02

## 原因

- 変更前は、ルーム発言の`targets`を省略すると、送信者以外の全メンバーへ配送していた。
- Botの返答も同じ入口を使うため、一つの返答が無関係なBotを起こし、そのBotの返答が次の全員を起こす連鎖になっていた。
- AIへ自然言語で無言を求めると「黙ります」等の応答自体は生成される。無応答をAIへ要求する設計では止められない。

## 実装した契約

- 受信したルーム発言には発言IDと`respond_to_room`の使い方を添付する。
- Botは`respond_to_room(action="reply")`または`respond_to_room(action="silent")`を返す。
- `silent`はBellTeam内部の制御結果として消費し、ルーム履歴へ記録せず、別のBotへも配送しない。AIがツール実行後に生成する通常の最終回答も従来どおりルームへ表示しない。
- Botが`targets`なしでルームへ投稿した場合は、ユーザーの画面へ表示するだけで他のBotを起こさない。
- 処理が必要なBotを`targets`へ明示した場合だけ、そのBotの待機列へ配送する。
- 特定の一人だけに必要な依頼、回答、連絡には`sendmessage`を使い、ルーム全員を起こさない。
- ユーザーまたはルーム予定が宛先を省略した場合は代表だけを起こす。代表未設定の一人部屋はその一人へ送り、代表未設定の複数人部屋は明示エラーにする。
