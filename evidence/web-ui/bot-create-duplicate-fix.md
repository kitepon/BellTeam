# Bot作成の多重送信修復

確認・修復日: 2026-09-01

## 原因

- 23:06:58〜23:07:43（Asia/Tokyo）に、同じ名前・人格・役割のBot作成が9回実行されていた。
- `POST /api/bots`はBotを永続化したあと、初回挨拶のAIターンが終わるまでHTTP応答を返していなかった。
- Web画面は応答を受け取るまで設定面を閉じず、保存ボタンの多重送信も防いでいなかった。そのため、待ち時間中の再タップがすべて別のBot作成になった。

## 修復

- Bot本体と個人記憶領域の作成後、初回挨拶をバックグラウンドで開始して作成結果を直ちに返すようにした。
- 初回挨拶の失敗は標準エラーへ記録し、作成済みBotの成功応答とは混同しない。
- Web画面はBotの保存処理を一度だけ受け付け、処理中の保存ボタンを無効化して「作成中…」または「保存中…」と表示する。

## 検証

- 初回挨拶を停止した状態でもBot作成APIが201を返し、作成処理と挨拶開始が各1回であることをfocused testで確認した。
- 同じ保存処理の二度目を拒否し、完了後だけ再実行できることをfocused testで確認した。
- ローカル画面で保存中ボタンが無効になること、初回挨拶の完了前に設定面が閉じること、作成後のBotが1体だけであることを確認した。
- 最終回帰は84件成功、失敗0件、skip 0件だった。
