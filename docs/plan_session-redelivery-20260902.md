# セッション不達時の再起動と再送

## 目的

BellTeamがボットの最後に確認したAitermセッションIDへメッセージを送り、不達なら新しいエージェントを起動してセッションIDを更新し、元のメッセージを一度送る。

## 変更範囲

- Aitermは、Cursorの入力欄へ本文が残っている実被弾画面を未送信として返す。
- BellTeamはボットの表示名、固定ID、最後のセッションIDを保存する。
- DMとルームの配送は、記録済みセッションへの送信失敗時だけAitermでエージェントを起動する。
- 起動結果のセッションIDをボット情報へ保存し、同じメッセージを一度送る。

## 非目標

- 配送キューの永続化
- 再送回数や複雑な復旧方針の追加
- セッション監視や常時起動
- 新しいセキュリティ対策、安全装置、追加ID体系

## 既知の罠

- AitermのPTYが存在しても、AIが入力を受理したとは限らない。
- Cursorは未送信の本文を`→ 本文`として表示する。この画面を空の入力欄と同じ正規表現で判定すると未送信を見落とす。
- BellTeamの現行プロフィールはセッションIDを常にボットIDへ戻すため、起動結果を保存しても再読込で失われる。

## 実装順

1. 実被弾したCursor画面をAitermのfocused testへ固定する。
2. Aitermが未送信を成功形で返さないよう修正し、関連試験を通す。
3. Aitermを公開し、BellTeamの利用版を更新する。
4. BellTeamへ最後のセッションIDの永続化と不達時の起動・一回再送を実装する。
5. DMとルームのfocused testを通し、本番で停止セッションから一往復を確認する。

## 受入条件

- 実被弾したCursor画面でAitermが`submit_residue=true`を返す。
- Aitermは残留本文を検出した配送を成功扱いしない。
- BellTeamは記録済みセッションへの送信失敗後、`agent_launch`が返したセッションIDを保存する。
- 再読込後も保存したセッションIDが残る。
- DMとルームの両方が新しいセッションへ元のメッセージを一度送る。
- 関連試験、全試験、公開版を使った本番smokeが成功する。

## 進め方

Aitermの返却契約へBellTeamが依存するため、二つの実装は直列に行う。別担当への委譲と並列書込みは使わない。

## 実測結果（2026-09-03）

停止状態の4ハーネス（Claude・Codex・Grok・Cursor）へ本番で送信し、記録済みsession（Bot ID）への不達→起動→一回再送の経路で全て受信・返信した。Claudeの初回配送失敗はAiterm側の起動待ち省略が原因で、Aiterm 0.29.30で修理した（詳細は`plan_cursor-cold-start-delivery-20260902.md`）。
