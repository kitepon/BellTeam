# ゴール一覧とチャットの表示

ゴール一覧は現在の取得結果で設定済みと確認できたゴールだけを表示する。取得不能・未対応のメンバーがいる場合は、その旨を示す。取得失敗を「未設定」に置き換えない。

個別チャットでは入力欄のすぐ上に小さな行を置き、タップすると上向きのカードに目的文・現在の状態・利用量と操作を表示する。ルームでは表示しない。Escape とカード外のクリックで閉じられる。参考画像は私有の確認資料とし、このリポジトリには含めない。

一覧とチャットは既存の同じ Goal API、取得結果、編集状態、操作処理を使う。チャット選択・カードを開く操作・既存の更新通知で取得し、チャットの通知処理は取得完了を待たない。変更要求の結果が不明な時は自動で再送しない。

編集・一時停止・再開・削除は応答の capabilities と fieldCapabilities に従う。正式 Native 0.61.21 の通常 Linux Codex では四操作を使えるが、目的文と予算の同時編集は行わない。Claude は一時停止・再開に未対応、Grok は編集・一時停止・再開に未対応で削除にも状態条件があり、Cursor は未対応。OS 別に実証されていない能力を画面側で有効にしない。経過時間は実応答がある場合だけ表示する。

検証結果:

- Goal 表示の focused 試験 21 件成功、失敗・中止・skip 0。
- 完了時の `TESTGATE_FULL=1 npm test` は 839 件成功、失敗・中止・skip 0。
- Chromium で実 Web アプリと HTTP Goal API・BotGoals・SDK wrapper を接続し、Native だけを人工実装に置き換えて確認。幅 390 / 1100 で小さな行、カード配置、設定済みだけの一覧、両画面の四操作を確認した。人工変更は計 8 回、再送・page error 0、ブラウザと HTTP サーバーは終了済み。

本番の反映、実 Bot のゴール変更、上流 provider、認証操作は行っていない。Native の未対応操作を追加する変更ではない。旧通信障害の回復と過去のデータ保持証拠は、この検証では確認していない。

## 選択と変更完了の順序修理

独立レビューで、一時停止 POST の待機中に別チャットへ移動して戻ると、選択時の仮表示から binding が消え、変更前に開始した GET が完了後の画面を進行中へ戻す反例が見つかった。変更完了時に、それ以前の取得結果を無効にする。現在の binding が確認できなければ不明を保持し、同じ binding が見えている場合だけ完了後に読み直す。別 thread の観測結果と、単発 POST・自動再送なしは維持する。

元の独立反例は旧 source で 1 fail → 修理後 1 pass。追加の確認は confirmed と応答喪失の両方で古い取得結果を採用せず、明示更新で paused を読めること。新 focused 22 件、完了時の明示 full 840 件成功（失敗・中止・skip 0）。画面配置と Chromium の先行成功は別証拠として保持し、この順序修理の再試験とは区別する。
