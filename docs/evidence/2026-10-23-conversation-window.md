# 会話の配置範囲と操作状態の保持

出典: `apple-performance-59`（`99a4585f6627980465ca75aa8c7667d61f9fae93`）からの差分、人工データのXCTest結果、専用Simulatorの座標記録、Macの起動記録。取得日: 2026-10-23。確度: 記載した環境と操作の実測。実機と配布後の結果は含まない。

会話の本文を配置する範囲を、画面とその上下2画面分へ絞った。画面外には測定済みの行高を使った余白を置き、未測定の行は180ptで仮置きする。初回最新10行、過去20行の取得、全件の本文データの保持は維持した。`LazyVStack`と明示的な末尾移動の組み合わせで停止する既知の条件を避け、配置する行を明示した`VStack`を使う。

## 高さと読書位置

- 本文・返信者表示・列の幅が同じ場合だけ測定値を再利用する。添付画像と入力カードを含まない本文行を再配置する間は、実測した最小高と上端の位置を保つ。画像とカードは内容に応じて縮むため、その実高を使う。
- 推定した余白を実際の行へ替える時は、全体が高くなる場合と低くなる場合の両方で、読んでいる行の位置を補正する。
- 過去取得直後に固定している行は、補正が終わるまで配置範囲へ残す。
- 範囲を替えるだけの時は位置を指定しない。高さが変わった時だけ補正し、利用者のスクロールを途中で止めない。
- 幅は内容が実際に配置された幅で測る。列幅の変更直後、古い幅の最小高を適用した行の計測は、新しい幅の測定値として保存しない。

最初の失敗では、過去追加後に固定行の上端を44.7へ戻せていたが、全体の高さが6922.7から6005.7へ縮むと行が-821へ動き、固定が解除されていた。旧処理が高さの増加だけを補正していたためである。iPadでは詳細パネルを閉じる時、旧幅594の設定と実際の幅894が混在する瞬間も実測し、測定値の再利用を修理した。

## 操作状態の所有

| 内容 | 所有者と寿命 |
| --- | --- |
| 本文と配置範囲 | `ConversationContent`。会話を閉じるまで保持する。 |
| 行の測定値、読書位置、カード状態の参照 | `ConversationContent`が保持する`ScrollTracker`。計測の更新で親全体を再描画しない参照型とする。 |
| 質問カードの下書き、送信中、結果、エラー | `OwnerQuestionCardState`。行を配置から外しても会話が保持し、カードだけが観測する。 |
| 秘密入力カードの結果 | `SecretRequestCardState`。行を再表示しても引き継ぐ。 |
| 秘密の入力値 | 従来どおり`SecretInputSheet`。画面を閉じた時と背景へ移った時に消す。会話の状態には保存しない。 |
| 画像・秘密入力・メンバー間連絡の画面 | 元の行が開閉を所有する。開いている間は行の入れ替えと明示的な末尾移動を保留し、閉じた時に末尾移動を再開する。 |

カードに独自のID、永続保存、配送処理は追加していない。既存のメッセージIDで会話内の状態を引き継ぐ。

既存のスクロール試験で、配置範囲の外にある本文は存在を確認してから操作可否を調べるようにした。条件とスクロール回数の上限は保ち、未配置の要素に対するXCTestの繰り返し検索を省く。新着ボタンを押した後は、最新行が実際に操作できる位置へ戻ることも確認する。

人工データは`PreviewFixtures`と`test/helpers/conversation-scroll-server.mjs`を使う。カードの試験は`-bellbot-preview-window-state`、秘密入力中の新着は`-bellbot-preview-window-state-updates`を併用する。実Bot、本人の会話、資格情報、未知POSTの再送は使わない。

## Macの未確認事項と残る負荷

MacのXCTestランナーは、ローカルの試験用署名と既存のApple Development署名の両方で、アプリのmainへ到達する前の`_libsecinit_appsandbox`からXPCを待った。対象アプリのフリーズとは判定せず、試験を中止した。本人のアプリは終了せず、別のBundle IDとビルド成果物を使った。

その後、別のBundle ID `dev.kitepon.bellbot.virtualization-final`で、プロジェクト既定の自動署名、Mac用entitlements、Apple Developmentチームを指定してfocused UI試験を再実行した。Xcodeはビルド段階で`No Accounts: Add a new account in Accounts settings`と報告し、Mac Catalystの仮profileにはCommunication NotificationsとPush Notificationsの権限がないと明示した。`mac-window-standard.log`と`mac-window-standard.xcresult`が原本である。この実行では試験アプリもランナーも起動せず、MacのUI試験結果は得られていない。正規の開発アカウントと必要なcapabilityを持つprofileが利用できる状態で再実行する必要がある。

通常起動した試験アプリへのJev操作では、会話の選択とAX値の設定が返った。しかし入力欄の値は画面で保持されず、スクロールは候補の確信度が不足して実行されなかった。Macの通常キー入力とスクロールは未確認であり、自動試験の成功には数えない。Mac向けのfocused試験は用意した。既存の通信試験がホームボタンをMac向けにもコンパイルしていた箇所は、iPhone・iPad用の試験として対象を明示した。

取得済み本文と測定値の保持は行数に比例する。配置範囲と余白の高さの算出にも、行数に比例する走査が残る。画面外のMarkdownの配置は省いたが、全処理を一定時間にしたとは主張しない。未測定行の全体高は推定値なので、測定が進むとスクロールバーが示す長さは変わる。実機の時間・CPU・メモリの比較、千行以上の測定、配布後の確認は行っていない。

証拠の原本は、この作業ツリーの`runtime/apple/conversation-window-20261023/`に保存する。`phone-final.log`と`phone-final.xcresult`（更新中操作2件成功、fixture URL不足による会話5件のskip）、`phone-scroll-final.log`（その5件をURL指定して再実行し5件成功）と結果要約JSON、`card-state.log`と`card-state.xcresult`、座標の`layout-trace.log.gz`、Macの`mac-runner-sandbox.sample.txt`、Mac試験ログが含まれる。iPadは`ipad-final.log`、`ipad-rotation.log`と各結果要約JSONにまとめた。

参照: [Appleの遅延スタックとスクロールの説明](https://developer.apple.com/videos/play/wwdc2026/321/)、[XCTestのスクロール操作](https://developer.apple.com/documentation/xcuiautomation/xcuielement/scroll%28bydeltax%3Adeltay%3A%29)。
