# GET時間切れの診断に必要な本体の記録

未解決の通信診断を調べる際、本体がGETの受付も終了も記録しないため、記録がない事を未到達の根拠にできなかった。APIのGET/HEADに受付と終了のログを加える。通信を直した扱いや、過去の診断の解決登録は行わない。

例:

```text
BellTeam read: 2026-10-15T05:00:00.000Z GET /api/bots started
BellTeam read: 2026-10-15T05:00:00.000Z GET /api/bots 200 15ms
```

応答が止まっている間は受付だけが残る。完了前の切断は `aborted`。SSEも接続の受付と閉鎖だけを残す。`finish` は端末の受領を証明しない。追加IDなしのため、同時刻に同じ経路の要求が重なればログだけの一意な照合はできない。アプリの時刻・経路・メトリクスとの照合を併用する。

本文、query、認証/Cookieヘッダーは出さない。既存の書込みログの形式を維持する。healthz、静的ファイル、内部MCPは対象外。通常のGETのたびに2行増えるため、既存のDockerログの30MB上限の下では保持期間は要求数に依存する。過去のGETの欠測を埋め戻すものではない。

隔離したHTTPサーバーで、通常GET、応答待ち中の受付、途中切断、500、HEAD、healthz除外、SSE配信中に追加ログが出ない事、query/ヘッダー非記録を検証する。書込みの正常/途中切断の既存試験も維持する。本番への通信試験は行わない。
