# Macのプロフィール表示と初期保存

取得日: 2026-10-03。出典: SwiftUIの実装、Macの実画面、試験用HTTPサーバーの受信記録。確度: 実測済み。

## 変更

- Macの会話の詳細ボタンを、右のプロフィールペインへ接続した。Macではプロフィール表示のsheetを作らない。Botの端末画面からも詳細ボタンでプロフィールへ戻る。従来のポップアップにあった会話セッションの再起動は右ペインへ置いた。
- メンバー編集のプロフィール初期値を同期的に用意し、モデル候補の取得と保存状態を分けた。モデル候補の通信中・取得失敗でも、元のプロフィールを保存できる。
- 実際の保存を試すと、独立した編集ウィンドウに通常のdismissを使っていたため閉じなかった。ウィンドウ所有者がdismissWindowで既存のmember-editorとBot IDを指定して閉じる形に直した。

## 検証

既存のDebug previewデータを使う専用サーバーでモデル応答を止めた。修正前のビルド32では、待機がタイムアウトしてAIの欄が表示された後も保存が灰色のままだった。修正版では、候補の読込中に保存ボタンが有効で、画像と入力を変えず保存できた。受信した名前、モデル、エフォート、プロフィール、アバター等は初期値を保持し、modelsPending=trueのままPATCHが届いた。

右ペインを非表示にし、会話の「さらに表示」をJev Desktopで押すと、同じ会話ウィンドウの右ペインへプロフィールが表示された。プロフィールのポップアップと新しいウィンドウは作られなかった。

MacのDebugビルドとUI試験のbuild-for-testing、初回のサーバー全331試験が成功した。他担当の会話ログ読込更新を取り込み、関連試験と統合後の全334試験も成功した。UI試験のケースは追加したが、XCTestによる実行はまだ行っていない。GUIの実操作はJev Desktopとagent-desktopで確認した。

画面・操作・受信記録はruntime/mac-editor-*とruntime/mac-profile-*に置いた。保存後とキャンセルで編集ウィンドウが閉じることも確認した。

ビルド34のiPhone・Macの署名・書き出し・Appleへのアップロードが成功した。このMacへの標準のinstall-mac.shによる導入・署名確認・起動も成功した。

統合したサーバー更新は別担当の会話ログ読込変更であり、今回のAppleアプリのコードとは重ならない。本番コンテナの再起動・再作成は行っていない。

Apple側でiPhone・Macともビルド34がVALIDとなり、Ownerグループへの登録とIN_BETA_TESTINGを読み戻した。記録はruntime/apple/mac-profile-34/testflight-34-proof.json。
