# App Storeの独自性審査への回答

この本文は、BellTeamのiOS版とMac版への4.3・4.2.6の指摘に回答する。送信と審査の現在地は[準備状況](subscription-setup.json)に記録する。

## Appleへの返信本文

ご確認ありがとうございます。BellTeamの具体的な機能と開発経緯について、9項目に回答します。

1. アプリの機能と解決する問題

BellTeamは、利用者が自分のPC・サーバーで動かす複数のAIメンバーと、iPhone・iPad・Macから仕事を進めるためのネイティブアプリです。利用者は自分の契約でClaude・Codex・Grok・Cursorを認証し、メンバーごとに名前、役割、モデル、プロフィールを設定します。各メンバーはサーバー上に専用の作業場所と継続セッションを持ちます。

個別の会話に加え、複数メンバーのルーム、返信するメンバーの指定、メンバー間の連絡、繰り返す仕事の予定、回答を選ぶ質問カード、秘密情報の専用入力、画像添付、返信通知、会話全件のJSON書き出しを扱えます。会話・設定・作業場所の正本は利用者のサーバーにあります。外出中のiPhoneから依頼や回答を行い、Macで同じ仕事を続けられます。

2. 対象ユーザー

AIの開発用CLIを使って調査・開発・文章作成などを行い、自分の作業環境とデータを管理したい個人開発者、技術者、制作者が主な対象です。PCで準備した複数のAI担当者へ、机を離れている間にも依頼や判断を返したい人を想定しています。サーバーの設置が必要であることを初回画面で案内し、導入手順をアプリ内で読めるようにしています。

3. 既存製品では満たしにくい必要性

利用者の課題は、複数のAIの端末、作業場所、会話、予定を個別に管理し、外出時の返答や判断も別々の入口で行うことです。BellTeamは、別々のCLIで継続して働く担当者を一つのチームとして扱います。たとえば、調査担当と実装担当を同じルームに入れて依頼し、各担当の役割と会話を保持したまま、iPhoneで追加指示や質問カードへの回答を行えます。サーバーはPC上で仕事を続け、アプリには新着の会話と通知が届きます。

この作業環境の管理と、複数担当者の会話・判断・予定をまとめる機能の組合せが本製品の中心です。AIへの単発の質問を送る機能だけを提供するものではありません。利用者は自分のAI契約とサーバーを使い、会話と作業環境を自分で保持します。

4. 提出前のβ試験と反映した意見

TestFlightの内部配布を使い、開発者本人がiPhoneとMacで日常利用して改善しました。大規模な外部ユーザー調査を実施したという主張はしていません。実機の利用確認に加え、iPhone・iPadシミュレーターとMac Catalystで画面・通信・共通処理を試験しています。

具体例は次のとおりです。
・送信の受付待ちで文章が入力欄に残るという指摘を受け、送信時に本文と画像を入力欄から外し、失敗時には下書きを戻す処理にしました。複数画像の添付と送信拒否時の復元を試験しました。
・保存済みのAIモデルが編集画面で「CLIの既定」と表示される問題を直し、候補の読み込み後に保存済みの選択を表示するようにしました。Mac実画面でも本人が確認しました。
・会話の更新中にスクロールや入力が止まる問題を調査して配置処理を修正し、iPhone実機のスクロール・キーボード・詳細画面と、Macの実トラックパッド操作で確認しました。
・初めて入手した人がサーバーの準備を理解できるよう、接続前に読める導入ガイドを追加しました。本人の提案でGitHubのURLとセットアップ依頼文をコピー・共有できる機能も追加しました。新規サーバーへの接続と、両端末へのビルド41の導入・起動を確認しました。

5. 同じ開発者アカウントのほかのアプリとの関係

BellTeamは独立した製品です。iOS版とMac版は同じApp Store Connectアプリ、同じBundle IDのプラットフォーム版であり、顧客・地域・AIごとに別のアプリを提出していません。

同じアカウントのほかの製品は次のとおりで、BellTeamの複数AI作業環境を提供する製品ではありません。
・ReminderBOT：Discordコミュニティの共有予定とリマインダー。
・Approval Box：AIから届く判断依頼の受信、回答、履歴と端末接続。
・結 Yui：複数メーカーの家庭用機器の操作とオートメーション。
・KITE BINGO：ビンゴイベントの主催・参加と抽選。
・Kikoeru：英語リスニングの学習。
・Nextflic：触覚を使う日本語フリックキーボード。

6. ほかのアプリへ統合しなかった理由

上記のアプリは、コミュニティの予定、判断依頼、家庭用機器、ゲーム、学習、キーボードという別の目的とデータを扱います。BellTeamが必要とするAIメンバー、CLIの継続セッション、専用の作業場所、ルーム、会話の管理はそれらの製品の機能に含まれていません。たとえばApproval Boxは判断依頼を受け取って答える製品で、AIメンバーを作成して日常の会話や作業を管理する製品ではありません。既存製品へ追加すると利用目的と初期設定が大きく変わるため、独立したBellTeamとして提供しています。iPhone・iPad・Macの利用権は一つの共通購読にまとめています。

7. 同じアカウントのアプリとのコード・素材の共有

BellTeamのiOS版とMac版は、同じ製品のため、SwiftUIの会話・編集・設定画面、API通信、StoreKit購読、通知処理、画像素材を共用しています。Mac版はMac Catalystを使い、一覧・会話・詳細の配置やキーボード操作をMac向けに実装しています。

上記の独立した6製品との間で、BellTeamの機能を構成する大きな共通コード、独自フレームワーク、画像素材は共有していません。標準のAppleフレームワークは各製品で使用しています。

8. 第三者のアプリとのコード・SDK・コンテンツの共有

他社のアプリを基にしたコードベースや、アプリ生成用のテンプレート、コンテンツライブラリーは使用していません。会話のMarkdown表示には通常のオープンソースライブラリーEnrichedMarkdownを使用しています。その役割は文字の描画・選択・コピーで、AIメンバー、ルーム、予定、サーバーAPI、質問カード、秘密入力、購読の機能はBellTeamの実装です。

AI各社の公式CLIは利用者のサーバーで動き、Appleアプリのバイナリーには同梱していません。アプリはBellTeamのAPIを通して会話や管理操作を行います。会話内容は利用者の依頼により生成され、他社アプリから複製したコンテンツを配布するものではありません。

9. 内容・企画・ブランドの提供者

BellTeamは当開発者アカウントの所有者自身が企画し、開発・運営する製品です。顧客や第三者から提供された内容・ブランドのアプリを代理で提出しているものではありません。アプリ内のブランドと同梱画像も、所有者自身が提供しています。利用者ごとにアプリを生成・提出するサービスは行っておらず、一つのBellTeamアプリから各利用者のサーバーへ接続します。

以上の具体的な用途、独自実装、試験と製品の区分をご確認いただき、BellTeamの審査を継続していただけますと幸いです。ご案内に従い、今回の回答のみを送信し、アプリの再提出は行っていません。
