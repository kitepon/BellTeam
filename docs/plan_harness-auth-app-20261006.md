# AI認証画面の配布と実認証の確認

目的は、AIの認証が切れてメンバーが止まった時に、オーナーがAppleアプリから公式認証へ入り直せること。実装・試験・両プラットフォームのTestFlight内部配布、端末の導入と、本番の本人操作を含む確認まで完了した。状態・配布物・検証結果は[準備状況の正本](subscription-setup.json)の`integration.appHarnessAuthentication`、実装と試験の説明は[検証記録](evidence/2026-10-06-app-harness-auth.md)を参照する。

## 完了した作業

1. Macへの導入・起動と認証状態の閲覧を確認した。iPhoneの修理候補の導入と起動も本人の回答で確認した。本番の認証確認はMacを使用した。
2. オーナーの進行GOを受け、トロニーが予定と受入の完了後に席の区切りを確認した。開始直前の連絡を届け、Macアプリから一度だけ認証を始めた。
3. Cursorの開始・待ち・取消・実状態の読み直しは本番のMacで完了した。Codexは、オーナーがスマホの公式サイトで承認し、Macの認証済み表示への遷移を確認した。
4. トロニーは更新された共有認証と、新しいCodexの実起動・応答を確認した。認証不在中の失敗は無く、席への復旧連絡も完了した。次の期限の見込みの確認と知らせの予定の更新も担当が行った。

Codexは開始時に今の認証を消すため、担当の直前確認を受け、本人へ発行したコードを渡して公式承認まで通した。Macの公式サイトはTouch IDの本人操作で止まったため、スマホの公式画面を使用した。試験専用の常設サーバーは無く、画面試験は本番と切り離したHTTP fixtureで行った。ASCへの再提出と本番コンテナの再起動はこのアプリの認証確認に含めていない。

今回の入り直しはアプリの画面から公式認証まで通った。コードの入力で止まった回答と添付を確認して訂正を案内し、認証を始め直さず完了を確認した。本人操作と、親の実画面の確認、担当の本番・実起動の確認は準備状況の正本で区別する。
