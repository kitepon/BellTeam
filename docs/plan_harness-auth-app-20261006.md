# AI認証画面の配布と実認証の確認

目的は、AIの認証が切れてメンバーが止まった時に、オーナーがAppleアプリから公式認証へ入り直せること。実装・試験・両プラットフォームのTestFlight内部配布は完了した。端末への導入と、本番の本人の操作を含む確認を待っている。状態・配布物・検証結果は[準備状況の正本](subscription-setup.json)の`integration.appHarnessAuthentication`、実装と試験の説明は[検証記録](evidence/2026-10-06-app-harness-auth.md)を参照する。

## 残る作業

1. Mac・iPhoneを最新の配布物へ更新し、設定のAI一覧と公式の現在の状態を確認する。閲覧の段階では認証を開始しない。Macの自動更新は操作ツールのアプリ読取りが失敗して実行できず、オーナーへ依頼した。
2. オーナーの許可後、開始前にトロニーへ連絡する。トロニーが実行中のCodex席が無いことを確認し、サーバーの観測を用意してから始める。
3. 先にCursorで開始・待ち・取消・実状態の読み直しを確認する。その後、オーナーがその場で公式サイトの承認を行える時間にCodexを最後まで通す。入力が必要な場合は同じ画面から渡し、認証済みへの遷移とメンバーの応答を確認する。

Codexは開始時に今の認証を消すため、2と3は許可前に実行しない。試験専用の常設サーバーは無く、今回の画面試験は本番と切り離したHTTP fixtureで行った。公式認証を最後まで通したとはまだ扱わない。ASCへの再提出と本番コンテナの再起動はこの作業に含めない。

詰まった時は操作を止めてトロニーへ連絡する。トロニーのAitermの公式認証入口による入り直しは運用の復旧であり、アプリで通った確認の代わりには数えない。Codexの入り直し後の期限の確認と知らせの予定の更新はトロニーが行う。
